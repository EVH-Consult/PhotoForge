# Milestone - v000.007-ms056 - filename-folder-timestamp-integration

File name: v000.007-ms056-filename-folder-timestamp-integration.md  
Commit message: ms056: integrate filename and folder timestamps

## Type

implementation

## Context

MS051 and MS052 implemented deterministic filename and folder extractors, but
the active scanner does not yet add their candidates to resolution. The
extractors are therefore isolated capabilities rather than end-to-end behavior.

## Goal

Complete filename and immediate-parent-folder timestamp integration for every
currently supported file before expanding the supported format set.

## Affected components

- `src/photoforge/scanner.py`
- `src/photoforge/timestamp_resolution.py`
- existing filename and folder extractors, by invocation only
- focused unit, integration, and E2E tests
- affected system documentation and golden outputs

## Behavior specification

For each supported file, candidate collection must occur in this exact order:

1. format metadata candidates, including EXIF where supported
2. filename candidates from `path.name`
3. folder candidates from `path.parent.name` only
4. filesystem mtime candidates

Resolution precedence remains EXIF → filename → folder → filesystem. Candidate
order within one source remains extraction order.

A valid date-only filename or folder candidate represents that calendar date at
`00:00:00`, retains `precision="date"` for provenance, and is eligible for
resolution only when its stored naive timestamp is exactly midnight. No timezone
may be inferred.

Invalid filename or folder values are ignored and cannot block fallback.
Diagnostics remain deterministic and do not influence selection.

## Deliverables

- scanner integration for filename and immediate-parent-folder candidates
- explicit resolver validity for deterministic date-only candidates
- regression tests for precedence, invalid fallback, immediate-parent scope,
  date-only midnight behavior, and candidate ordering
- updated golden outputs and module documentation
- green Windows/Linux Python 3.10/3.12 CI matrix

## Non-goals

- adding TIFF or any other file format
- reading ancestors beyond the immediate parent
- changing extraction patterns
- inferring local timezones
- changing hashing, grouping, planning, reporting, or operations semantics

## Invariants

Identical file bytes, path names, parent-folder names, metadata, and mtime
produce identical candidate order, selected timestamp, diagnostics, and plan.
No directory enumeration order or operating-system path separator may affect
selection.
